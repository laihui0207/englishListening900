## 1. 任务目标

在自习室白板（`public/whiteboard.html` + `whiteboard.js`，原生 JS 单 canvas 全量重绘）上增加思维导图能力，参考效果：中心主题 → 多级分支，贝塞尔连线，每条支线一种颜色。

分两轮完成：

| 轮次 | 内容 |
|---|---|
| 第一轮 | 调研最佳实现方案 → 用户拍板 5 个决定 → 实现 MVP（放根、加子、改字、删除、整图移动、撤销） |
| 第二轮 | 折叠子树（－ 按钮 / 数量徽标）+ 拖动节点改序、改层级 |

## 2. 用户拍板的决定

1. 点「导图」按钮后**再点画布**决定中心主题位置，不是立即放到视口中心。
2. **不用模板**，第一次只画一个根节点；悬停节点时左右出现 ＋，点 ＋ 生成下一级。
3. 编辑态**回车只确认**，不自动生成同级。
4. 工具栏的全局颜色 / 粗细选择器**不作用于**导图节点；每条支线可以单独配色（属性面板改色作用于节点及其后代）。
5. 连线粗细**随缩放变化**（世界单位，与其他图形和 PNG 导出一致）。

---

## 3. 方案选择

调研流程：14 个 agent（5 份调研、3 份候选设计、3 位评委、1 份综合、2 份对抗核查）。

**结论：不引第三方库，自绘。**

- 现成导图库（jsMind、mind-elixir、simple-mind-map、markmap）全部是 DOM / SVG 渲染，布局依赖 DOM 测量，嵌进单 canvas 白板会造成双视口、双选中、导出 / 小地图 / 持久化不一致。
- 纯布局库里只有 d3-flextree 贴合（3.3 KB），但 5 年未更新，且「最紧凑」排布会让分支交错。目标布局用约 60 行纯函数即可精确复现。
- 三个候选建模：A 单个复合图形（淘汰：hitTest / eraser / undo 全要开特例）、C 节点即图形、H 务实混合。最终以 H 为骨架、移植 C 的交互，两者数据模型相同。

**核心设计：节点即图形，连线派生。**

- 每个节点是 `shapes` 数组里一个普通 `{x, y, w, h}` 图形，`type: 'mind-node'`，树关系靠 `mapId / parentId / side / order` 扁平存储。
- 父子连线不落盘，在子节点自己的 `drawShape` 分支里按 `parentId` 画三次贝塞尔。主画布、小地图、PNG 导出三处循环因此同时生效，无需额外改动。
- 布局是「子树 band 高度累加 + 父节点居中于首尾子节点」两趟 DFS，O(n)，支持左右双侧。
- 现有的 bbox / hitTest / translateShape / 框选 / 持久化 / nextId 对 mind-node 零改动可用。

## 5. 功能行为速查

### 创建与编辑
- 「导图」工具 → 点画布放中心主题，自动切回选择工具并进入编辑，「中心主题」四字全选。
- 悬停 / 选中节点：朝外一侧出现 ＋（根两侧都有）。有子节点时显示 －、＋。
- Tab 加子节点、Enter 加同级、F2 或双击改文字、Delete 删整条子树（提示可撤销）。
- **多行文字**：编辑时 Shift+回车换行；单行超过节点最大宽（260）自动折行，中日韩任意处可断、拉丁词按空格断；节点高按行数增长，文字块在框内居中；编辑框是贴合节点的 textarea，字号 / 行高 / 内边距随缩放同步。
- 边打字节点边变宽变高、兄弟让位；新建的空节点 Esc 直接删除并撤回创建记录。
- 深层节点长到视口外时自动平移视口。

### 折叠
- 点 － 折叠整棵子树；折叠后只显浅色圆形徽标，数字 = 被折叠的后代数，常显；点徽标展开。
- 折叠的节点不绘制、不可点选、不参与框选 / 全选 / 小地图 / 导出 / 橡皮擦；布局时收进折叠节点位置，展开恢复。
- 对折叠节点加子会先自动展开；根和叶子不能折叠。

### 拖动
- 拖**非根节点** = 换位置 / 换层级，整棵子树跟指针走；拖**中心主题** = 搬整图。
- 指针落进节点内 → 成为它的末尾子节点（目标粗边框高亮）；落到根的左 / 右半边决定挂哪一侧。
- 指针在某一列节点上方 / 下方 → 插成该节点的兄弟（显示插入线）。只认指针所在的那一列。
- 换到别的分支整支跟新父同色；升到根下按一级规则领新色；同父调序不改色；层级变化字号随深度调整。
- 拖到空处、拖回原位、指针未离开原框都弹回且不记撤销；拖动中 Esc 取消；目标折叠时自动展开。

### 颜色
- 一级分支依次取 6 色板，子孙继承父色。
- 全局色板 / 粗细对导图节点无效；属性面板的描边色 / 粗细作用于该节点及全部后代。

### 审查修掉的主要问题

第一轮：
- 拖拽进行中按 Ctrl+Z 会被下一帧 drag.orig 盖回去 → 拖动中不响应撤销。
- 每个键击一条撤销记录 → 输入过程只重排不入栈，提交时记一条。
- textInput 的 `min-width:140px` 会撑破 96px 宽的节点 → 节点模式单独 class。
- 属性面板盖住下方兄弟 → 对导图节点放右上角。
- 撤销后立即 PUT 绕过防抖 → 统一走 `scheduleSave`。
- `WBHistory` 在 cap=1 时不限长；`layout` 对缺 w/h 产生 NaN；加载坏数据修复后不重排。

第二轮：
- **手抖 5px 就改层级**：落点原来在 160px 内总能找到候选（往往是父节点）→ 只认指针所在的那一列，且指针未离开原框不给落点。
- **布局祖先上溯可死循环**（成环且都折叠的坏数据）→ 步数上限。
- **撤销基线被拖动中途状态覆盖**（快照的延迟提交可能落在拖动中）→ 拖动中改用拖动开始时的快照。
- 拖动中 Delete 会删掉正在拖的子树 → 拖动中除 Esc 外不响应按键。
- 拖动中定时保存会把悬空子树写到服务端 → 拖动中推迟保存。
- 根带 collapsed 的坏数据会让整图消失 → repair 清掉。
- 徽标字号与圆圈口径不一致、缩放时溢出 → 同用世界单位。
- 橡皮擦擦到折叠节点时后代闪现 → 擦除时连带子树。
